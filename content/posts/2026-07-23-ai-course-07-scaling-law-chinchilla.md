## 第7课：模型越大越好吗 —— 预训练、Scaling Law 与 Chinchilla 直觉

### 本课目标

前六课我们把"一个模型内部如何运作、如何被训练"讲完了：token → embedding → Transformer → 位置编码 → 损失与优化器。但有一个工程师最关心的问题还悬着：**给定一笔固定的算力预算，我应该训一个多大的模型、喂多少数据？** 这就是 **Scaling Law（缩放定律）** 要回答的。学完这一课，你能解释：为什么 GPT-3（175B）其实"吃不饱"，而参数只有它 1/2.5 的 Chinchilla（70B）反而更强——以及"参数量不是唯一 KPI"这个如今行业共识是怎么来的。

### 今日经典案例

DeepMind 2022 年的 **Chinchilla**（Hoffmann et al., *Training Compute-Optimal Large Language Models*）。它用一句话改写了大模型训练的方法论：**在固定算力下，模型参数量 N 和训练数据量 D 应该大致等比例增长**，经验值约 **20 个 token / 每参数**。

### 背景铺垫

**1. 预训练（pre-training）是什么。** 就是第2、6课讲的那件事的"工业规模版"：在海量无标注文本上做 next-token prediction，用交叉熵损失（第6课）反向传播更新权重。没有人工标注，"标签"就是文本里的下一个词。这一步烧掉了训练的绝大部分算力，产出一个"什么都懂一点"的基座模型。

**2. 三个核心变量。**
- **N**：模型参数量（权重个数）。
- **D**：训练消耗的 token 总数（数据量）。
- **C**：计算量（FLOPs，浮点运算次数）。

有一个必须记住的**估算公式**：

```
C ≈ 6 · N · D   （FLOPs）
```

直觉：每个 token 走一次前向+反向，每个参数大约摊到 6 次浮点运算（前向约 2 次乘加，反向约 4 次）。这个公式是理解 Scaling Law 的钥匙——**算力预算 C 一旦定死，N 和 D 就是一个"此消彼长"的天平**：模型翻倍大，能喂的数据就得减半。

**3. 幂律（power law）。** Scaling Law 的核心观察是：测试损失 L 随 N、D 增大而下降，且在 log-log 坐标上近似一条直线，即

```
L(N, D) ≈ E + A/N^α + B/D^β
```

- E 是"数据本身的熵"这类不可约误差（irreducible loss），无论多大模型都消不掉；
- A/N^α 是"模型不够大"带来的误差，B/D^β 是"数据不够多"带来的误差；
- α、β 是拟合出来的指数（约 0.3–0.5）。

**类比**：想象你在拧两个都能降低噪音的旋钮（模型大小、数据量）。任何一个拧到底、另一个不动，噪音都降不下去——因为另一项 `/N^α` 或 `/D^β` 会卡住你。最优策略是**两个旋钮一起拧**。

**4. 数据配比（data mixture）。** D 不只是"多少"，还有"什么成分"：网页、代码、书籍、多语言各占多少。配比影响模型的能力侧写（比如代码占比高则编程强）。本课重点在"量"，配比先建立概念即可，后续课程展开。

### 回到 Chinchilla

在 Chinchilla 之前，业界（GPT-3、Gopher 280B）的做法是"**把参数尽量堆大，数据量差不多 300B token 就够了**"。Chinchilla 团队做了一件朴素但昂贵的事：训练了 400 多个不同 (N, D) 组合的模型，在 `C≈6ND` 约束下拟合上面的幂律公式，然后求解——**给定 C，什么样的 N 和 D 让 L 最小？**

答案是：此前的大模型**普遍数据喂得太少、参数堆得太多**（undertrained）。最优配比下 N 和 D 应同比例放大，落地经验就是 **D ≈ 20·N**。于是他们用和 Gopher **相同的算力**，训了一个**只有 70B 参数但喂了 1.4T token** 的 Chinchilla——参数少了 4 倍，数据多了约 4 倍——结果在几乎所有下游任务上**全面超过 280B 的 Gopher**。

这带来一个额外的"免费午餐"：更小的模型**推理更便宜、更省显存**（回顾第1课的 KV Cache 与显存瓶颈）。所以 Chinchilla 不只是"训得更好"，而是"训完之后天天用起来也更省"。这也解释了后来 LLaMA 系列为何敢用小参数量+超大数据量的路线。

一个重要**边界**：20:1 是"训练算力最优"的比例，不是"部署最优"。如果一个模型要服务上亿次请求，把它训得比 Chinchilla 定律更小、喂更多数据（"过度训练"）反而总成本更低——这正是今天很多开源小模型的选择。

### 动手 / 思考

**练习1（算一算，纸笔即可）。** GPT-3 是 N=175B 参数、D=300B token。按 Chinchilla 的 20:1 定律，175B 参数"应该"配多少 token？你算出的数字和它实际的 300B 差几倍？这个差距说明 GPT-3 处于"吃饱"还是"饿着"的状态？

**练习2（几行代码，画出幂律直觉）。**

```python
import numpy as np
C = 1e21                      # 固定算力预算 (FLOPs)
N = np.logspace(8, 11, 50)    # 参数量从 1e8 到 1e11
D = C / (6 * N)               # 由 C≈6ND 反解数据量
# 玩具版损失公式（指数为演示值）
L = 0.7 + 400/N**0.34 + 400/D**0.28
best = N[np.argmin(L)]
print(f"最优参数量 ≈ {best:.2e}, 对应 D ≈ {C/(6*best):.2e}, D/N ≈ {C/(6*best)/best:.1f}")
```

跑一下，观察 L 随 N 变化是一条"先降后升"的 U 形曲线：太小则 `/N^α` 项大，太大则数据被挤压导致 `/D^β` 项大。最低点附近的 D/N 比值，就是"计算最优"的配比——体会 Chinchilla 求解的本质。**思考**：如果把预算 C 提高 10 倍，最优的 N 大约会往哪个方向移动？
