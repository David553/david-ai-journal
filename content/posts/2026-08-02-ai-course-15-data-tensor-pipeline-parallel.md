## 第15课：一张卡装不下，就用一群卡 —— 数据并行、张量并行与流水线并行

### 本课目标

前面我们把"单张 GPU 上一个模型怎么算"讲透了：算力与带宽（第13课）、数值精度与 kernel（第14课）、优化器状态占的显存（第6课）。但第7课的 Scaling Law 告诉我们，模型要大、数据要多。一个 70B 模型光是 BF16 参数就要 140GB，再加梯度和 Adam 状态（后面第16课细讲），轻松突破 1TB —— 一张 80GB 的 A100 **根本装不下**。就算装得下，用一张卡训练也要几百年。

所以现代大模型训练一定是**分布式**的：把工作切开，分给几百上千张 GPU。本课回答一个核心问题：**当模型和数据大到单卡放不下时，有哪几种"切法"，各自的通信代价是什么？** 这是理解一切大规模训练系统的骨架。

### 今日经典案例

没有合适的新论文，我们用**Megatron-LM**（NVIDIA，2019）作案例 —— 它奠定了 Transformer **张量并行**的标准做法，至今几乎所有训练框架都在用它的切法。

### 背景铺垫

#### 先建立一个新工具：集合通信原语

多卡协作的本质是"交换数据"。GPU 之间通过高速链路（机内 NVLink，跨机 InfiniBand）通信，业界把常见的通信模式抽象成几个**集合通信原语**（collective communication）。你只需先记住两个：

- **All-Reduce**：每张卡各有一份数据（比如各自算的梯度），把所有卡的数据**按元素相加**，再把这个总和**发回每一张卡**。结束后每张卡都拿到完全相同的求和结果。类比：4 个人各记了半天的账，凑一起加总，然后每人都抄一份最终总账。
- **All-Gather**：每张卡各有一"片"（一部分），操作后每张卡都**拿到拼起来的完整版**。类比：每人手里一块拼图，交换后每人都有整幅图。

关键直觉：**通信是要花时间的**，而且受带宽限制（第13课的 memory-bound 逻辑在这里升级成"communication-bound"）。切模型的艺术，就是**在少通信的前提下把活分匀**。

下面看三种正交的切法。

#### 1. 数据并行（Data Parallelism, DP）——切数据

最简单：每张卡放一份**完整的模型副本**，但各自只处理这个 batch 的**一部分数据**（比如 4 张卡，全局 batch=32，每卡算 8 条）。

- 各卡独立前向、反向，算出**各自的梯度**；
- 因为数据不同，梯度也不同，但它们应该被平均成"整个 batch 的梯度"——这里做一次 **All-Reduce** 把梯度加总平均；
- 每张卡用相同的平均梯度更新参数，于是副本始终保持一致。

优点：实现简单、扩展性好。缺点：**每张卡都要装下整个模型**——所以 DP 解决"算得慢"，不解决"装不下"。

#### 2. 张量并行（Tensor Parallelism, TP）——切单层里的矩阵

当一层本身就大到装不下，就得把**一个矩阵乘法**切开，让多张卡合算一层。这叫**层内并行**。看 Megatron 怎么切 Transformer 的 MLP（回忆第4课：`Z = GeLU(X·A)·B`）：

**第一步，A 按列切**：`A = [A₁ | A₂]`，卡1 算 `X·A₁`，卡2 算 `X·A₂`。妙处在于 GeLU 是逐元素的，`GeLU(X·A₁)` 和 `GeLU(X·A₂)` 各自独立成立，**这一步不用通信**。

**第二步，B 按行切**：`B = [B₁; B₂]`，卡1 算 `Y₁·B₁`，卡2 算 `Y₂·B₂`，两者相加才是最终结果 `Z = Y₁B₁ + Y₂B₂`。这里做一次 **All-Reduce** 求和。

```
卡1: X·A₁ → GeLU → Y₁ → Y₁·B₁ ┐
                                ├─ All-Reduce(相加) → Z
卡2: X·A₂ → GeLU → Y₂ → Y₂·B₂ ┘
```

于是整个 MLP 只需前向 1 次、反向 1 次 All-Reduce。代价是通信极频繁（每层都通），所以 TP **只在机内用 NVLind 高带宽时才划算**，很少跨机器。它把单层的参数和激活都切小了，是"装不下"的主力解法。

#### 3. 流水线并行（Pipeline Parallelism, PP）——按层切

再换个方向：把模型的**不同层**放到不同卡上。卡1 放第 1–8 层，卡2 放第 9–16 层……数据像流水线一样，前一段算完把激活传给后一段。这叫**层间并行**。

问题来了：卡2 得等卡1 算完才能开工，其它卡在**空转**——这段浪费叫**流水线气泡（bubble）**。解法是把一个 batch 切成很多**micro-batch**，让它们像工厂流水线上的零件一样鱼贯而入：卡1 处理完第 1 个 micro-batch 就交给卡2，自己立刻开始第 2 个。micro-batch 越多，气泡占比越小。

```
时间 →
卡1: [mb1][mb2][mb3][mb4]
卡2:      [mb1][mb2][mb3][mb4]
卡3:           [mb1][mb2][mb3][mb4]   ← 开头结尾的空档就是 bubble
```

PP 的通信量最小（只在层的边界传激活），适合跨机器；但调度复杂，且有 bubble 损耗。

#### 三者是正交的：3D 并行

DP（切数据）、TP（切层内矩阵）、PP（切层）互不冲突，可以**叠加**。训练 GPT-3 级别模型的典型配置：机内 8 卡用 TP，跨机若干组用 PP，再在最外层用 DP 复制多份。三个维度组合，就是所谓 **3D 并行**，也是 Megatron-LM 后续版本的核心。

### 回到案例：Megatron-LM 的贡献

Megatron 的洞见很朴素却关键：**顺着 Transformer 的结构切，就能把通信降到最低**。MLP 用"先列切、后行切"，让非线性 GeLU 夹在中间却不产生额外通信；注意力层则天然按**注意力头**切（第1课多头注意力），每个头独立计算，最后同样一次 All-Reduce 合并。整个 Transformer block 在前向+反向里只需**固定几次 All-Reduce**，与层的宽度无关。正是这个"结构感知的切法"，让张量并行成为大模型训练的标准件。

### 动手 / 思考

**思考题 1**：数据并行里，如果每张卡的 batch 太小，会发生什么？（提示：回忆第13课，decode 为什么 memory-bound——小 batch 下 GPU 算力"喂不饱"，通信占比还会升高。这解释了为什么 DP 不能无限切。）

**思考题 2**：为什么张量并行几乎只在一台机器内部（NVLink）用，而流水线并行敢跨机器用？用"每一步通信多少、多频繁"来回答。

**玩具代码**：手算一次数据并行的梯度 All-Reduce，体会"各卡不同 → 求和平均 → 各卡一致"。

```python
import torch
# 假设 2 张卡，各自 batch 的梯度（这里用标量模拟一个参数的梯度）
grad_gpu0 = torch.tensor([2.0, -1.0])
grad_gpu1 = torch.tensor([4.0,  3.0])
# All-Reduce(求和) 再除以卡数 = 全局平均梯度
world_size = 2
avg = (grad_gpu0 + grad_gpu1) / world_size
print(avg)          # 两张卡拿到完全相同的 [3.0, 1.0]，用它同步更新
```
