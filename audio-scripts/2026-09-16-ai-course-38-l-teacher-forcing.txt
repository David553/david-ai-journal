第38课：一次前向，学会 L 步 —— 因果掩码、Teacher Forcing 与训练/推理的不对称

本课目标

前面 37 课里，你已经分别学过「自回归生成」（第2课）、「Transformer block」（第4课）、「KV Cache 与 decode 的 memory-bound」（第1、13课）、「反向传播与 autograd」（第37课）。但有一个把它们缝在一起的关节，我们一直绕着走：训练时模型明明也是自回归的，为什么一次前向就能算完 4096 个位置的 loss，而推理却必须一个 token 一个 token 地吐？

这一点值得停下来想想。图像分类里一张图只有一个标签，监督信号极其稀疏；而语言模型每个 token 都是一个完整的 V 类分类任务的标签。这是预训练效率高得离谱的根本原因，也解释了第7课里 Scaling Law 的 C ≈ 6ND 为什么用 token 数 D 而不是「样本数」来计量数据——每个 token 都真的贡献了一次梯度。

2. 代价：不能偷看

密集监督不是白拿的。它成立的前提是：位置 i 的表示，绝对不能包含 t_{i+1} 及之后的任何信息。

否则会发生什么？自注意力是全连接的，位置 i 本来就能看到位置 i+1 的 embedding。而位置 i 的任务是预测 t_{i+1}。那模型只要学会一件事——「把我看到的下一个位置的内容复制出来」——loss 就直接降到 0。这就是标签泄漏（label leakage），模型什么都没学会，但训练曲线漂亮得不行。

类比：开卷考试，每道题的答案印在下一页，而你被允许翻页。

为什么是 -inf 而不是 0？ 这是新手最常踩的坑。因为 exp(-inf) = 0，掩掉的项在 softmax 的分子和分母里同时消失，剩下的权重重新归一化，行和仍然是 1。如果你偷懒在 softmax 之后把权重置零，分母里那些项还在，剩余权重的和就小于 1 了——相当于给不同位置施加了不同强度的随机缩放，训练会很难看。

工程细节：实际代码里常用 torch.finfo(dtype).min 而不是字面 -inf，因为 -inf 参与某些融合 kernel 或与 0 相乘会产生 NaN；在 bf16 下写死 -1e9 也不安全（bf16 能表示，但和 fp32 混算时容易出问题），用 finfo().min 最稳。

5. Teacher Forcing：并行的真正前提

现在回答开篇的问题。训练时，位置 i 的输入是数据集里真实的 t_i，而不是模型自己在上一步预测出来的 token。这个做法叫 teacher forcing（老师强制喂正确答案）。

正因为所有位置的输入都是已知常量，整个序列可以一次性堆成矩阵做一次大矩阵乘。因果掩码保证了「虽然算在一起，但信息不串门」——并行计算，串行语义。

推理时则没有老师。位置 i 的输入只能是模型自己刚吐出来的 token，于是必须真的串行 L 步。

这就带来 exposure bias（曝光偏差）：训练中模型永远站在「完全正确的前缀」上做预测，而推理中一旦某步出错，它就进入了训练时从未见过的前缀分布，后续预测质量塌方，错误雪崩式累积。这和第12课 Agent 的 p^n 误差累积是同一件事的两个面孔——Agent 的每一步动作都是自己生成的，没有任何老师，所以长程任务格外脆弱。

缓解手段有两类：scheduled sampling（训练中按概率混入模型自己的预测，概念）；以及更彻底的——在模型自己的 rollout 上训练，这正是第22课 RLVR/GRPO 的深层动机之一。RL 阶段的数据分布天然就是推理时的分布，exposure bias 从定义上被消除了。

6. 第二种 mask：padding

一个 batch 里的序列长度通常不齐，短的要右侧 pad 到同长。于是需要第二种 mask，它和因果掩码是正交的两件事：

- causal mask：(L, L)，位置方向的，「不许看未来」，全 batch 共享
- padding mask：(B, L) 作用在 key 维度上，「不许看 pad 位」，每条样本不同

最终两者按位与，广播成 (B, 1, L, L) 喂给注意力。同时 loss 也要 mask——把 pad 位置的标签设成 ignore_index=-100，并且用有效 token 数而非 B*L 做分母，否则不同 batch 的 loss 量级会随 padding 比例乱跳。

顺带指出：第9课 SFT 的 loss masking（只对 assistant 回复算 loss）用的是完全相同的机制，只是 mask 的语义从「这是填充」变成了「这是不该学的 prompt」。

padding 的浪费在长文本上很可观。工程上的解法是第24课讲过的 sequence packing：把多条短序列拼成一条满长度序列，再用 document mask 阻断跨文档注意力。现代实现更进一步，用 varlen 接口（FlashAttention 的 cu_seqlens）直接传边界偏移数组，连 mask 矩阵都不构造。

7. 收口：同一个因果结构，两种利用方式

最后把它接回 infra。

训练/prefill：Q 是 (L, d) 的矩阵，Q @ K.T 是 (L,d)×(d,L) 的大 GEMM，算术强度高 → compute-bound。这就是第13课说 prefill 吃算力的原因，prefill 本质上就是训练的前向传播。

decode：Q 只有一行，(1,d)×(d,L) 是 GEMV，为了算这一个 token 必须把整个 KV Cache 从 HBM 读一遍 → memory-bound。

有意思的是：因果掩码让训练得以并行，KV Cache 让推理免于重算——两者其实是同一个因果结构的两种红利。正因为位置 i 的表示永远不依赖 i 之后的内容，历史的 K/V 才永远不会被改写，缓存才有意义。如果模型是双向注意力（第11课 ViT），新增一个 token 会让所有旧位置的表示全部失效，KV Cache 根本不存在。

回到案例：nanoGPT

nanoGPT 的 CausalSelfAttention 把上面全部串起来了：register_buffer 预先存一个 tril 下三角常量 → masked_fill(-inf) → softmax → @ V。这是教学版本。

它还有一个快路径：F.scaled_dot_product_attention(q, k, v, is_causal=True)。注意这里传的是一个布尔标志而不是 mask 张量——这恰恰是第26课 FlashAttention 的关键工程收益：mask 根本不物化成 (B, H, L, L) 的显存，而是在 tiling 循环里直接跳过右上角的整块。省掉的不只是 L² 的显存，还有接近一半的 FLOPs——被掩掉的那半个矩阵，压根就没算过。
