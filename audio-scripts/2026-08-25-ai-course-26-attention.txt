第26课：注意力算不起了怎么办 —— FlashAttention、稀疏/线性注意力与 token 压缩

本课目标

第5课我们知道了自注意力是 O(L²)，也知道上下文窗口是个硬约束；第13课学了 Roofline 和 HBM 带宽；第14课学了 kernel 融合。但一直缺一块拼图：当序列真的长到 32K、128K，注意力那一项具体贵在哪，工业界用哪几种手段把它做下来。 这是路线图 A.4「位置编码、上下文窗口与长文本」里"长文本"那一半，也是理解今天几乎所有长上下文架构论文的钥匙。

学完你能回答：为什么 FlashAttention 不减少一次乘法却能快好几倍？滑窗注意力凭什么还能"看见"远处？线性注意力为什么能把 KV Cache 变成固定大小、代价又是什么？以及看到一篇"压缩 token 做全局交互"的新架构时，该问它哪几个问题。

今日论文

ProxyFormer（arXiv 2608.23463）提出双流架构：每层把细粒度局部特征自底向上压成一小组 proxy token，只在这个压缩空间里做昂贵的全局注意力，再自顶向下注入回局部流——本课末尾我们用刚学的概念拆它。

背景铺垫

一、先把账算清楚：L² 出现在两个地方

一层注意力（batch=1，d 为模型维度，多头合起来算）：

- 算力：QKᵗ 是 2L²d FLOPs，AV 又是 2L²d，合计 ≈ 4L²d。而 Q/K/V/O 四个投影矩阵是 8Ld²。两者相等的临界点是 L = 2d。d=4096 时临界长度约 8K：短序列里注意力只是配角，超过 8K 它就变成主角。L=32K 时注意力项 ≈17.6 TFLOPs，投影项 ≈4.4 TFLOPs，4 倍差距。
- 显存：朴素实现要把 L×L 的注意力分数矩阵物化（materialize）到 HBM 里，好让反向传播用。L=32768、32 个头、bf16：32 × 32768² × 2 bytes ≈ 69 GB——一层就装不下一张卡。

第二条其实更致命，而且它揭示了一个反直觉的事实：这 69 GB 的写入和读出是纯粹的搬运。用第13课的算术强度看，朴素注意力 kernel 干的是 memory-bound 的活，GPU 的 TensorCore 大部分时间在等 HBM。

二、精确路线：FlashAttention —— 不改数学，只改访存

关键洞察：那个 L×L 矩阵根本不需要落地。它只是中间产物，最终我们只要 L×d 的输出。如果能分块计算、算完就丢，HBM 里就再也不出现 L² 的东西。

障碍是 softmax：它要对整行做归一化，天生需要"看完全行"。破解它的是 online softmax（流式 softmax）——把归一化拆成可增量维护的三个量。回忆第2课的数值稳定技巧 softmax(s)ᵢ = e^{sᵢ-m} / Σe^{sⱼ-m}，其中 m 是最大值。我们维护 running max m、running 分母 l、未归一化的输出累加器 O，逐块吃进 K/V：

数学上和一次性 softmax 完全等价（不是近似！），但每块的 s 只有几 KB，可以留在 SM 的 SRAM 里。这就是第14课"算子融合"的极致版本：QKᵗ → 缩放 → softmax → AV 四步融成一个 kernel，中间量不出 SRAM 的门。

代价与收益：

- HBM 访问量从 Θ(Ld + L²) 降到 Θ(L²d²/M)（M 是 SRAM 容量）。d=64、M=100KB 时后者小几十倍。
- FLOPs 一点没少，甚至反向传播时为了不存 L×L 矩阵还要重算一遍分数——这是第16课"重计算换显存"的老配方，在这里同时还省了访存，纯赚。
- 这类算法有个名字：IO 感知（IO-aware）算法。它优化的不是运算次数，而是存储层级之间的搬运量。看到"我们的方法 FLOPs 不变但快 3 倍"，八成属于这一类。

FlashAttention 让长上下文从"跑不起来"变成"跑得起来"，但 L² 的算力项还在。要突破它，只能动数学。

三、近似路线：三种改数学的方式

(1) 稀疏 / 滑动窗口注意力. 让每个 token 只看最近 w 个邻居，复杂度降到 O(Lwd)，线性。担心"看不到远处"？其实单层看 w，两层就能看 2w——有效感受野随层数线性扩张，32 层 × w=1024 就是 32K。但纯滑窗有个致命 bug，第1课埋过伏笔：attention sink。开头几个 token 承载了异常大的注意力质量，一旦滑出窗口，模型输出直接崩坏。修法极简：永久保留最前面几个 token + 滑动窗口（StreamingLLM 的做法）。现代长上下文模型常是"少数几层全局 + 多数层滑窗"的混合模式，理由很实用：全局层负责跨文档检索，滑窗层负责局部语法，KV Cache 只需为全局层保留全长。

(2) 线性注意力. 注意力的本质是 outᵢ = Σⱼ sim(qᵢ,kⱼ)·vⱼ / Σⱼ sim(qᵢ,kⱼ)。softmax 的 exp(qᵗk) 不可分解，所以必须先算出 L×L 才能乘 V。如果换一个可分解的相似度 sim(q,k) = φ(q)ᵗφ(k)（φ 是某个特征映射，比如 elu(x)+1），矩阵乘法的结合律就能救场：

复杂度变成 O(Ld²)，对 L 线性。更漂亮的是 decode：令状态 S = Σⱼ φ(kⱼ)vⱼᵗ（一个 d'×d 矩阵），每来一个 token 只需 S ← S + φ(k_t)v_tᵗ，输出 φ(q_t)ᵗS。KV Cache 变成固定大小、与序列长度无关的状态——它其实就是一个 RNN。第17课的 PagedAttention 要解决的碎片问题，在这里从根上消失了。

代价是真实的：全注意力能对任意一个历史 token 做精确检索（associative recall，"大海捞针"），而线性注意力把整段历史压进固定大小的 S，容量一满就必然覆盖。这也是这条路线至今没取代全注意力的原因，也是 Mamba 类模型往往要混合几层全注意力的原因。

(3) token 压缩. 不改注意力公式，改参与注意力的 token 数：把 L 个 token 压成 m 个摘要 token（proxy / latent token），全局交互只在 m 个上做，O(m²)，m 是常数。这就是信息瓶颈思路。风险显然：压缩是有损的，一次压丢的信息，后面各层再也拿不回来。

回到论文：ProxyFormer 怎么补上压缩的漏洞

ProxyFormer 走的是第 (3) 条路，它的设计恰好针对上面那个风险：

- 双流（dual-stream）：L 个 token 的局部流跨层一直保留，不被替换；另有一条 m 个 proxy token 的全局流。
- 每层三步：自底向上压缩（局部 → proxy）→ 只在 proxy 空间做全局注意力（这里是唯一的 O(·²) 项，而 m≪L）→ 自顶向下注入（把带全局上下文的 proxy 广播回局部流）。
- 关键论点：因为局部流没被丢掉，某一层压缩没抓到的细粒度信息，后续层还有机会重新抓——把"一次性有损压缩"变成"多轮可修正的压缩"。

放进本课坐标系：它不是 FlashAttention 那种精确加速（数学变了），也不是滑窗（没有硬性局部约束），而是"压缩 + 残差旁路"——你会注意到，自顶向下注入回局部流，本质上就是第4课的残差流思想在跨粒度上的复用。评估它该问三个问题：m 取多少才不掉点？压缩/解压本身的 O(Lmd) 开销是否吃掉了收益？以及第21课的老规矩——质量等价前提下再比吞吐，否则数字没有意义。
