第35课：让模型听见、看得久 —— 音频/视频的 token 化与 Omni 模型的 KV Cache

本课目标

路线图第 10 项「多模态」我们已经讲了两次：第11课把图像接进 LLM（ViT → projector → 图像 token），第30课把图像离散化成 token（VQ-VAE / codebook）。但多模态还剩一块没补：带时间轴的模态——音频和视频。

这两者和图像有本质区别：图像是一个固定大小的二维信号，视频和音频是长度可以无限增长的一维时间流。于是问题从"怎么编码"变成"一秒钟值多少个 token"。学完这节课，你应该能回答：

- 一段 30 秒语音进到模型里，到底变成了多少个 token？这个数字是谁决定的？
- 为什么"长视频理解"在工程上其实是一个 KV Cache 容量问题，而不是模型能力问题？
- 为什么在纯文本 LLM 上验证过的 KV Cache 量化方法，搬到 Omni 模型上会崩？

今日论文

OmniKVQuant: KV Cache Quantization for Omni-LLMs（arXiv 2609.11582）：把音频/视频/文本混在一条序列里的 Omni 模型，其 KV Cache 的统计特性和纯文本完全不同；作者指出两个具体病灶（时间上的 key 漂移、模态间的 value 几何差异），用两个 training-free 的修补把 KV Cache 压到 2-bit。

2. 音频：波形 → 频谱图 → token

麦克风录下来的是波形：每秒 16000 个采样点（16 kHz 采样率）。如果一个采样点算一个 token，30 秒语音就是 48 万 token——显然不行，而且单个采样点毫无语义，就像把一张图按单个像素切 patch。

标准做法是先转到频域。直觉类比：波形是"空气压强随时间抖动"的流水账，而人耳听到的是音高和音色，也就是这段抖动里含有哪些频率成分。短时傅里叶变换（STFT） 就是把这本流水账切成小段，每段问一句"你由哪些频率叠加而成"：

- 窗长 25 ms：一次看一小段（足够短，段内可认为频率成分稳定）
- 帧移（hop） 10 ms：每次往后挪 10 ms → 每秒 100 帧

每帧得到一个频谱向量，再用一组模仿人耳分辨率的梅尔滤波器（mel filterbank） 压成 80 维，取对数 → log-mel 频谱图，形状 [100T, 80]。到这一步，音频已经变成了一张"图"：横轴时间、纵轴频率。剩下的事就和视觉编码器一样了。

Whisper 的编码器就是这么干的：log-mel 进两层 stride=2 的卷积，帧率 100 → 50，再过 Transformer；接到 LLM 前通常再池化一次，落到 12.5～25 token/秒。算笔账：30 秒语音 ≈ 375～750 token，和一张高分辨率图差不多。

这条路走的是连续 embedding 注入（和第11课的 projector 同构），用于理解。如果要让模型生成声音，就得像第30课那样把音频离散化——这就是 neural audio codec：编码器把每帧压成向量，再做 VQ 查码本。但音频对保真度敏感，一层码本误差太大，于是用 RVQ（残差向量量化）：第一层码本量化完，把残差再送进第二层码本量化，叠 8 层，每帧产出 8 个 token。代价是 token 数又乘以 8，而且这 8 个 token 是"同一时刻的不同精度层"，怎么排进一维序列（逐帧展平？还是分轨？）本身就是个设计难题。

3. 视频：token 预算的暴力现实

视频更直接：它就是一串图像。第11课说过一张 448×448 的图约 256～1024 个 token。那么 1 fps 采样的 10 分钟视频 = 600 帧 ≈ 15 万～60 万 token。这已经超过大多数模型的上下文窗口，更别说 KV Cache 显存。

所以视频模态的全部工程智慧，都是在做减法：

- 降帧率：1 fps 甚至 0.5 fps，代价是丢失快速动作；
- 时空 patch 合并：把相邻 2 帧的同位置 patch 合并成一个 token（3D patch），token 数直接减半，代价是时间分辨率减半；
- 换模态存储：干脆把视频先 caption 成文字存起来，查询时再按需取回原始帧——今天另一篇论文 CFD（2609.11899）走的就是这条路。

还有一个容易被忽略的点：时间位置怎么编码。文本 token 的位置是一维的（第5课 RoPE），但视频 token 有 (时间, 高, 宽) 三个坐标，音频 token 有绝对时间戳。Qwen2-VL 系的 M-RoPE 把 RoPE 的频率维度切成三段，分别编码 t/h/w，这样"第 3 秒左上角"和"第 5 秒左上角"才有正确的相对关系，音画也才能按时间戳对齐。

5. 量化的新工具：旋转

第14课讲过量化的核心难题是 outlier：量化 scale 由最大绝对值决定，一个离群值会把所有正常值挤进极少数量化格子里。当时的解法是 per-channel / 分组量化。

还有一招更巧的：旋转（rotation-based quantization）。注意力分数是 $QK^\top$。取任意正交矩阵 $R$（$RR^\top = I$），令 $Q' = QR,\ K' = KR$，则

$$Q'K'^\top = QRR^\top K^\top = QK^\top$$

注意力分数完全不变，但 $K'$ 的每个分量都是原始各维度的加权混合——离群值的能量被摊平到所有维度上了。实践中 $R$ 取 Hadamard 矩阵（元素只有 ±1，可以 $O(d\log d)$ 快速变换）。这就是 QuaRot / TurboQuant 这类方法的骨架：先旋转，再低比特量化，误差大幅下降。

回到论文

现在 OmniKVQuant 的两个发现就是白话了。

病灶一：temporal key drift（时间上的 key 漂移）。 文本序列的 K 分布大致平稳，所以可以给整条序列定一个量化范围。但音视频流不是——说话人换了、镜头切了，K 的数值范围沿时间轴整体漂移。用全序列的 min/max 定 scale，等于让最吵的那几秒决定全部 20000 个 token 的精度，安静段落被压成一片零。解法：按短时间窗口分别设定 key 的量化范围。本质上是把"per-channel 分组"的思想从特征维搬到了时间维——因为这个模态的非平稳性长在时间轴上。

病灶二：heterogeneous value geometry（模态间的 value 几何不同）。 旋转矩阵能摊平 outlier，前提是它和数据的协方差结构匹配。但音频段的 V 和视频段的 V 来自不同编码器、分布几何完全不同，共用一个 $R$ 等于给两种数据用同一副眼镜，至少有一方是虚的。解法：按模态分别旋转 V。这在实现上是免费的——V 只在 $\text{softmax}(\cdot)V$ 里被加权求和，对 V 做正交变换后在输出端转回来即可，不同段用不同 $R$ 也不破坏任何等价性。

两招叠加，training-free 地把 KV Cache 干到 2-bit（相比 fp16 省 8 倍），七个音视频 benchmark 上基本无损。

这篇论文本身方法不复杂，但它是一个漂亮的"三层贯通"样本：模态表示决定了 KV Cache 的分段结构 → 分段结构破坏了量化方法的平稳性假设 → 于是修补要打在假设上，而不是加大比特数。
