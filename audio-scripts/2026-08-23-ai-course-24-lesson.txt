第24课：模型吃什么就长成什么 —— 预训练数据管线：清洗、去重与配比

本课目标

第7课我们讲了 Scaling Law：算力 C ≈ 6ND，Chinchilla 告诉你 D 该有多大。但那节课把 D 当成了一个凭空存在的数字。第23课讲了文本怎么变成 token。今天补上中间最脏也最关键的一环：这些文本从哪来，凭什么算一个"有效 token"。

学完你能解释：为什么号称 15T token 的语料是从 100T+ 原始网页里榨出来的；为什么"去重"是预训练里性价比最高的一步；为什么"再多训一个 epoch" 不等于"多了一份数据"；以及为什么调数据配比这件事，比调模型结构更能决定模型能力。

今日案例

没有合适的新论文，用经典系统：RefinedWeb / Falcon（2023）。一句话——它证明了只用 CommonCrawl 网页数据，经过严格过滤和去重，不掺任何人工精选语料（书籍、arXiv、Wikipedia），训出的模型就能打平甚至超过用 The Pile 这类精选混合语料训的同规模模型。也就是说：清洗+去重的杠杆，比"找到好数据源"更大。

背景铺垫

1. 原始素材长什么样

预训练网页数据几乎都源自 CommonCrawl：一个非营利组织从 2008 年起持续爬取全网的公开快照，每月一版，每版几十 TB。它有两种格式：WARC（原始 HTML）和 WET（官方抽好的纯文本）。几乎所有严肃的数据管线都不用 WET，因为它的抽取太粗糙，会留下大量导航栏、Cookie 提示、页脚版权。RefinedWeb 从 WARC 重新用 trafilatura 这类工具抽正文——这一步的质量差异，最后会直接体现在模型能力上。

然后是几道粗筛：URL 黑名单（成人/赌博/垃圾站，以及评测集来源站点，对应第21课的数据污染）、语言识别（fastText 分类器打语种分，低于阈值丢弃）。

2. 质量过滤：三种打分器

"高质量"没有严格定义，工程上就是三类打分器的组合：

（a）启发式规则（Gopher 那套最经典）：文档词数在 50–100,000 之间；平均词长 3–10 字符；以 bullet 开头的行不超过 90%；以省略号结尾的行不超过 30%；至少 80% 的词含字母；至少包含 2 个常见停用词（the/of/and…）。这套规则专杀的是模板页、目录页、关键词堆砌页。

（b）分类器过滤：训一个轻量分类器（fastText 或小 BERT），正样本用 Wikipedia / 被 Reddit 高赞引用的网页，负样本用随机 CommonCrawl，然后按分数卡阈值。GPT-3 和 Llama 都用过这招。

（c）困惑度过滤（CCNet）：用干净语料训一个 n-gram 语言模型，对每篇网页算困惑度（第2课的概念），太高的是乱码、太低的是模板重复文本，两头都砍。

⚠️ 关键认知：过滤器编码了"什么是好文本"的价值判断。已有研究反复发现，这类过滤会系统性地误伤方言、非主流英语变体和小语种。过滤强度是个可调旋钮，不是越狠越好。

3. 去重：本课的技术重点

为什么必须去重？ 四个理由：① 重复文档让模型逐字背诵（memorization），后果是隐私泄露和吐出原文；② 重复意味着你以为的 D 是虚的，有效数据量缩水；③ 重复的评测题会渗进训练集，造成污染；④ loss 曲线会虚假下降——模型只是在背它见过的东西。

精确去重很简单：整篇文档做哈希，同哈希的只留一份；子串级别的重复（比如所有页面共享的免责声明）用后缀数组找出长度 ≥50 token 的重复片段删掉。

模糊去重才是难点：两篇文档差一个日期、差一句广告，哈希完全不同，但内容基本相同。我们要的是"相似度 > 0.8 就算重复"。

先定义相似度。把文档切成 n-gram 集合（RefinedWeb 用 5-gram），两篇文档的 Jaccard 相似度：

$$J(A,B) = \frac{|A \cap B|}{|A \cup B|}$$

直接两两算是 O(N²)——十亿文档就是 10¹⁸ 次比较，绝无可能。MinHash 解决这个问题，它基于一个漂亮的定理：

> 对一个随机哈希函数 h，令 $h_{\min}(A) = \min_{x \in A} h(x)$，则 $P[h_{\min}(A) = h_{\min}(B)] = J(A,B)$。

直觉：并集里的每个元素都有均等机会成为"最小值"，而只有当这个最小值恰好落在交集里时，两边才相等——概率正好是 |A∩B|/|A∪B|。于是用 k 个不同哈希函数各取一次最小值，得到长度为 k 的签名向量，签名的逐位相同比例就是 J 的无偏估计，误差约 $\sqrt{J(1-J)/k}$。一篇文档从几万 token 压成 128 个整数，还保留了相似度信息。

但签名两两比还是 O(N²)。最后一层是 LSH（局部敏感哈希）分带：把 k 位签名切成 b 个 band，每个 band 含 r 位（k = b·r），只要有任意一个 band 完全相同，就把两篇文档放进同一个候选桶。碰撞概率是：

$$P(\text{候选}) = 1 - (1 - J^r)^b$$

这是一条 S 形曲线，拐点约在 $(1/b)^{1/r}$。调 b 和 r 就等于调"判定为重复"的阈值。这样只需对同桶内的少量文档做精算，整体退化成近线性。RefinedWeb 用了 9000 个哈希分成 20 个 band（每 band 450 位），阈值对应 J ≈ 0.8。

顺带一个 infra 直觉：这整套是 CPU 集群 + 分布式存储的活，不是 GPU 的活。大厂预训练里，数据管线消耗的工程人力经常超过训练代码本身。

4. 数据配比：怎么混

数据分域：网页、代码、数学、书籍、论文、多语言、对话。自然分布下网页占 90%+，但自然分布绝不是最优分布。经验上，加代码数据能提升自然语言的推理能力；数学和论文虽占比小却影响上限。定权重目前有两条路：

- 小模型消融：拿 1B 模型跑几十组配比，看下游指标。贵，但直接可信，大厂主流做法。
- DoReMi：训一个小代理模型，用组间 minimax 的思路自动调权重——哪个域的"超额损失"（相对参考模型学得更差）大就加权重，学出的权重再拿去训大模型。省钱，但迁移性有争议。

重复训练（epoch） 是配比的另一面。高质量数据不够怎么办？重复。data-constrained scaling 的研究给了个实用结论：重复到 4 个 epoch 以内，效果接近于用等量新数据；超过约 16 个 epoch，边际收益基本归零。 所以第7课的 D 应该改写成"有效 token 数"——去重后的量，加上重复带来的打折。

还有个便宜的技巧：退火（annealing）/中期训练。训练末期把配比切换到高比例精选数据，同时衰减学习率。Llama 3 报告过这一步带来的显著提升，性价比远高于从头改配比。

5. 从文本到训练 batch

最后一公里：文档 tokenize 后，长度参差不齐，直接按最长补 padding 会浪费算力，所以做 packing——把多篇短文档首尾相连切成定长 L 的序列。副作用是：同一条序列里，后一篇文档能注意到前一篇（第5课的位置编码也会跨文档连续递增）。严谨的做法是加 document mask（禁止跨文档注意力）并在文档边界重置 position id。很多实现图省事跳过这步，代价是引入了轻微的训练噪声。

回到案例：RefinedWeb 的 MDR 管线

现在整条链路可以串起来了。RefinedWeb 的 MacroData Refinement 就是三段：

1. 文档准备：URL 黑名单 → 从 WARC 用 trafilatura 抽正文 → fastText 语言过滤。
2. 过滤：Gopher 那套启发式规则 + 行级重复检测（专杀导航栏、点赞数这类残留）。
3. 去重：MinHash + LSH 模糊去重（5-gram，阈值 0.8）→ 精确子串去重。

累计下来，原始 CommonCrawl 只剩约 10%，而去重这一步单独就砍掉了剩余数据的近一半——也是消融中收益最明显的一步。产出约 5T token（公开释出 600B），Falcon-40B 用其中 1T token 训练，在同期同规模模型里达到 SOTA。

论文真正的贡献不是某个规则，而是一个反直觉的结论：在"精选数据源"和"大规模严格清洗"之间，后者才是可扩展的那条路——因为前者的量有天花板，后者随 CommonCrawl 一起增长。这也直接回答了第7课留下的问题：Chinchilla 公式里那个 D，是这么来的。
