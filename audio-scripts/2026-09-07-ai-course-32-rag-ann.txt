第32课：给模型接一个外挂大脑 —— 检索增强生成（RAG）与向量检索的 ANN 索引

本课目标

课程路线第 2 项「向量、Embedding 与相似度」我们只讲到了一半：第3课讲清了什么是 embedding、点积/余弦相似度、以及「语义检索就是找最近邻」。但怎么在一亿条向量里把最近邻找出来，当时是一句话跳过的。第12课讲 Agent 时提到「长期记忆与检索」，也是同样的欠账。今天补上这个缺口——它同时是路线第 2 项的检索侧和第 11 项的 infra 侧。

学完你应该能回答：为什么不能靠微调给模型灌知识；为什么「把向量都乘一遍」在亿级规模下不是算力问题而是带宽问题（第13课的 roofline 会再用一次）；HNSW 和 IVF-PQ 到底在换什么；为什么几乎所有生产 RAG 系统都是「先粗召回再精排」两段式；以及分块（chunking）为什么是个恼人但绕不开的设计。

今日经典案例

今天没有合适的新论文，用经典案例：RAG 原论文（Lewis et al., 2020, *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*）——它第一次把「可训练的检索器 + 生成器」端到端拼成一个模型，并且给出了一个至今仍成立的结论：知识可以放在参数外面，热替换。

背景铺垫

1. 参数化知识 vs 非参数化知识

第7课讲过，模型的知识是压在权重里的，加知识的代价 ≈ 重新训练（$C \approx 6ND$）。这带来三个硬伤：更新贵（今天的新闻要等下一次训练）、无法溯源（说不出答案出自哪句话）、容易编（参数里的记忆是有损压缩，取不到就顺口造）。

RAG 的思路是把知识拆成两份：权重里的是参数化记忆（语法、推理、常识），外挂索引里的是非参数化记忆（具体事实）。生成时先检索、再把原文放进上下文。注意这不等于「上下文工程」的小技巧——它是一个架构选择：知识库和模型解耦，各自独立演进。

2. 检索的形式化，以及为什么暴力不行

把 $N$ 篇文档编码成向量 $\{z_i\} \subset \mathbb{R}^d$，查询编码成 $q$，检索就是最大内积搜索（MIPS）：$\text{top-}k\ \arg\max_i q^\top z_i$。（向量归一化后，内积 = 余弦相似度，见第3课。）

算笔账。$N = 10^8$，$d = 768$，fp32：
- 算力：$2Nd = 1.5 \times 10^{11}$ FLOPs，A100 上 bf16 峰值 312 TFLOPS → 0.5 ms。
- 访存：每个向量 $768 \times 4 = 3$ KB，全库 307 GB，2 TB/s HBM → 150 ms，而且一张卡根本装不下。

算术强度 $= 2Nd / 4Nd = 0.5$ FLOP/byte，深度 memory-bound——这是第13课那张 roofline 图最左边的位置。结论：向量检索的瓶颈从一开始就是「每条向量占几个字节」和「要读几条」，不是浮点算力。 所有 ANN（近似最近邻）索引都在优化这两个数字，只不过要付出一点召回率。

于是核心权衡是个三角：recall@k（真值 top-k 被找回的比例）× QPS × 内存，三个只能要两个。

3. 少读一些：IVF 倒排索引

先对全库做 k-means，得到 nlist 个质心（比如 4096 个），每条向量归到最近质心的桶里。查询时只算 $q$ 和质心的相似度，挑最像的 nprobe 个桶扫描。扫描量从 $N$ 降到 $N \cdot \text{nprobe}/\text{nlist}$——nprobe=16, nlist=4096 就是 256× 加速。

代价：真正的最近邻可能恰好落在簇边界另一侧没被 probe 到，直接漏掉。nprobe 就是那根旋钮：调大 → recall 升、QPS 降。

4. 每条读得更少：乘积量化 PQ

这里可以直接复用第30课的码本（codebook）：把 768 维切成 $m=96$ 个 8 维子向量，每个子空间独立训一本 256 条目的码本，于是每个子向量只存一个 uint8 的码号。一条向量从 3072 字节压到 96 字节，32× 压缩，$10^8$ 条 → 9.6 GB，单卡装得下。

5. 聪明地读：HNSW 图索引

另一条路线不分桶，而是建一张可导航小世界图：每个向量是一个节点，连 $M$ 个近邻。关键在多层结构——最上层稀疏、边很长，往下逐层变密变短，本质就是跳表的高维版。查询时从顶层入口贪心走：看当前节点的邻居里谁离 $q$ 更近就跳过去，走不动了就下一层。上层负责「打车横穿城市」，底层负责「走街串巷」，复杂度约 $O(\log N)$。

6. 为什么必须要有 rerank

embedding 检索用的是双塔（bi-encoder）：query 和 doc 各自独立编码，唯一的交互是最后那一个点积。这是个严重的信息瓶颈——整篇文档被压成一个定长向量，没机会「看着这个 query 再决定强调哪部分」。好处是 doc 向量可以离线算好、建索引。

对照的是 cross-encoder：把 query 和 doc 拼成一条序列过 Transformer，token 级充分交互，精度显著更高——但它无法预计算，$N$ 篇文档就要 $N$ 次前向，不可能全库跑。

所以生产架构必然是两段：双塔召回 top-100~1000（廉价、有损） → cross-encoder 精排 top-5（昂贵、准确）。这个「廉价草稿 + 昂贵验证」的模式你已经见过两次了：第18课的投机解码，第30课 DALL·E 用 CLIP 做 best-of-N 重排序。

7. 分块与混合检索

既然一个向量装不下一本书，就得切块。chunk 太大 → 主题被平均掉，信号被稀释；太小 → 丢上下文（「它」指谁没了）。常见做法：带重叠切分（overlap 保住跨界句子）、或parent-document 检索（用小块做匹配、返回它所属的大块给 LLM）。

另外，稠密检索对精确术语很差（型号 A100-SXM4-80GB、错误码），这类靠词频的 BM25 稀疏检索反而稳。二者互补，用 RRF（倒数排名融合）把两个排序合起来是很便宜的收益。

最后提醒两条上限：召回不到的东西，生成阶段无论多强都变不出来；以及塞进上下文的顺序也有影响，中间位置的证据容易被忽略（lost-in-the-middle，和第5课位置编码相关）。

回到论文

现在 RAG 原论文可以一句话串起来了。它的检索器是 DPR（BERT-base 双塔），文档库是切成 21M 个 100 词 passage 的 Wikipedia，索引用 FAISS 做 MIPS；生成器是 BART-large。

它的核心建模是把检索到的文档当成潜变量并做边缘化，而不是简单拼接：

$$p(y|x) \approx \sum_{z \in \text{top-}k(q)} p_\eta(z|x) \cdot p_\theta(y|x,z)$$

- RAG-Sequence：整句共用一篇文档，按序列做加权（上式）。
- RAG-Token：每生成一个 token 都重新在 $k$ 篇文档上边缘化，因此一句话可以从不同文档取不同事实。

训练时只微调 query encoder 和生成器，doc encoder 冻结。原因纯粹是 infra：动了 doc encoder 就得把 21M 条向量重编码并重建索引。这是个极好的例子——系统成本反过来塑造了算法设计，而且他们发现冻结并不掉多少分。

最能说明「非参数化记忆」价值的是那个索引热替换实验：把 2016 年的 Wikipedia 索引换成 2018 年的，模型对「某国领导人是谁」的回答就跟着更新了，一次训练都没做。对比一下第7课的 $C \approx 6ND$，这个性价比差异就是 RAG 至今没被淘汰的根本原因。
