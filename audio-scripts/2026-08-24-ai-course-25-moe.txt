第25课：一个模型养一群专家 —— MoE 的稀疏激活、路由与负载均衡

本课目标

第4课我们把 Transformer 拆成了「注意力 + MLP + 残差流」，但当时留了一个没戳破的事实：MLP 层才是参数大头（一个标准 block 里，FFN 约占 2/3 参数）。今天要讲的 MoE（Mixture-of-Experts，混合专家）就是对这一层动的手术，它是当前几乎所有前沿开源大模型（DeepSeek-V3、Qwen3、Mixtral、GPT-OSS）的默认架构。

学完这一课，你能解释这些问题：

- 为什么一个模型可以宣称"671B 参数"，却说自己"每 token 只激活 37B"？第7课的 C ≈ 6ND 还成立吗？
- 为什么 MoE 训练便宜、但 serving 反而更难？它到底卡在显存还是带宽？
- 为什么 MoE 模型的很多"通用小技巧"（比如激活层干预、剪枝、量化）一到 MoE 上就失灵？

今日论文

RARE: Decoupling Representation Steering from Expert Routing in MoE Language Models（arXiv:2608.21236）—— 发现在 MoE 模型的残差流上做"行为操控"会失效，原因是扰动顺带改掉了路由决策，解法是把扰动向量投影到路由矩阵的零空间里，让路由"看不见"这个扰动。

背景铺垫

1. 密集模型的死结：参数量和算力是绑死的

回顾第7课：训练算力 C ≈ 6ND。这个公式背后有个隐含前提——每一个 token 都要流过模型的每一个参数。这就是 dense（密集）模型。

于是想变强只有一条路：加参数 → 算力线性涨 → 推理时每个 token 的 FLOPs 也线性涨。Scaling Law 说更多参数能记更多知识，但你不一定希望"回答 1+1"也把全部知识过一遍。

2. 条件计算：把"参数量"和"每 token 算力"解耦

核心思想一句话：参数放在那里，但每个 token 只用其中一小部分。

类比：一家大医院有 256 个专科医生（参数量很大），但你挂号时前台（router）只把你分给 2 个相关科室（激活量很小）。医院越大，能治的病越多；但你的就诊成本只跟看几个医生有关。

具体做法：把 Transformer block 里那一个大 FFN，换成 N 个小 FFN（称为 expert，专家），外加一个极小的路由器。

- 激活参数量 N_act：决定每 token 的 FLOPs。

第7课的公式要改写成 C ≈ 6·N_act·D。DeepSeek-V3 是 671B 总参 / 37B 激活——训练算力按 37B 收费，知识容量按 671B 走。这就是 MoE 的全部卖点。

4. 负载均衡：MoE 最大的工程坑

路由器是学出来的，而学习有马太效应：某个专家早期稍微好一点 → 被选中更多 → 拿到更多梯度 → 变得更好 → 被选中更多。最终少数专家吃掉所有 token，其余专家饿死。这叫 路由塌缩（routing collapse），等价于你花了 671B 的显存，实际只用了 70B 的容量。

(b) 容量因子与 token 丢弃。工程上每个专家的 buffer 是预分配的固定大小 capacity = capacity_factor × (tokens / N) × k。超出的 token 直接被丢弃（跳过 FFN，只走残差连接）。所以训练时真的会有 token"没被计算"。

DeepSeek-V3 提出的 aux-loss-free 方案更优雅：给每个专家的路由 logits 加一个可调偏置 b_i，只用于 top-k 选择、不进入最终权重，然后按专家过载/欠载情况在训练中动态增减 b_i。相当于用一个不产生梯度干扰的"配额调节旋钮"替代了辅助损失。

5. MoE 在系统层的代价

MoE 不是免费午餐，它把算力问题转换成了显存 + 通信问题：

- 显存：671B 参数全都要驻留。这是第15课并行策略的新一维——专家并行 EP（Expert Parallelism）：不同专家放在不同 GPU 上。
- All-to-All 通信：token 在哪张卡上、专家在哪张卡上，两者不匹配。每个 MoE 层都要一次 all-to-all 把 token 发到目标专家的卡上，算完再发回来。这是不规则、延迟敏感的通信（对比第19课 dense 推理里规整的 all-reduce），也是 MoE 推理的头号瓶颈。
- decode 更惨：第13课讲过 decode 是 memory-bound。dense 模型 batch 变大能摊薄权重读取成本；但 MoE 在大 batch 下，batch 里的不同 token 会路由到几乎所有专家——你还是得把所有专家权重从 HBM 读出来，算术强度提升远不如 dense。这就是"MoE 训练省钱、serving 不一定省钱"的根本原因。

6. 路由是离散的，所以脆弱

回到伪代码里的 topk。它是 argmax 家族，输入的微小扰动可能把排名第 2 和第 3 的专家整个对调。dense 模型里你给隐状态加个小向量，输出是连续平滑变化的；MoE 里同样的操作可能让 token 换了一整套 FFN 参数——输出发生不连续的跳变。

回到论文：RARE 怎么绕开路由

表征工程（representation engineering） 是一种轻量的模型行为控制手段：先找出一个代表某种行为的方向向量 v（比如"拒答"或"正式语气"），推理时直接在某层残差流上加上去：h' = h + λv。不用训练、不改权重。在 dense 模型上很好用。

RARE 的观察是：在 MoE 上直接这么干会失效，而且他们做了对照实验——如果人为保持路由不变（用原始 h 算路由、用扰动后的 h' 算专家输出），操控效果大幅恢复。同时他们发现路由对语义内容很敏感、对行为变化本身不敏感。结论很清楚：破坏来自"扰动把 token 送错了专家"，而不是扰动本身有问题。

RARE 的解法非常干净：让路由器看不见这个扰动。

路由器就是一个矩阵 W_r ∈ R^{N×d}。我们希望扰动 v' 满足 W_r·v' = 0，这样 W_r(h + v') = W_r·h，路由 logits 一模一样，top-k 选择、权重全都不变；但送进专家的向量确实变了，行为操控照常生效。
