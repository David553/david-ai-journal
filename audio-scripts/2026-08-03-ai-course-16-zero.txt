第16课：训练时显存都去哪了 —— 参数、梯度、优化器状态、激活与 ZeRO

本课目标

第13课我们算清了"算力和带宽"，第14课谈了"数值精度占几个字节"，第15课把模型"切到多张卡上"（DP/TP/PP）。但有一个账我们一直没细算：训练一个 7B 模型，推理时权重才 15GB，为什么训练却连 80GB 的 A100 都装不下？ 学完这一课你能精确回答这个问题，并理解 DeepSpeed / PyTorch FSDP 背后那个"消除数据并行冗余"的核心思想。这是进入"推理生命周期与 Serving"之前，训练侧的最后一块基础拼图。

经典案例

ZeRO（Rajbhandari et al., 2020，《ZeRO: Memory Optimizations Toward Training Trillion Parameter Models》）。它是 DeepSpeed 的基石，也是 PyTorch FSDP 的思想来源。没有花哨的新算子，只是把显存账算到了极致。

背景铺垫

训练显存分两大类：
- 模型状态（model states）：参数、梯度、优化器状态。跟 batch size 无关，是"固定开销"。
- 残余状态（residual states）：主要是激活（activations），即前向传播时为反向传播缓存的中间结果。跟 batch size 和序列长度成正比。

先算模型状态。回忆第14课的混合精度、第6课的 Adam。现代训练标准配方是 fp16/bf16 混合精度 + Adam。设参数量为 Ψ，逐项记账（单位：字节/参数）：

| 项目 | 精度 | 字节 |
|---|---|---|
| 参数副本（前向用） | fp16 | 2Ψ |
| 梯度 | fp16 | 2Ψ |
| 优化器状态：fp32 主权重 | fp32 | 4Ψ |
| 优化器状态：Adam 一阶动量 m | fp32 | 4Ψ |
| 优化器状态：Adam 二阶动量 v | fp32 | 4Ψ |

为什么优化器里还要存一份 fp32 主权重（master weights）？因为 fp16 只有 10 位尾数，w -= lr*grad 时，微小更新会被"舍入吞掉"（第14课的下溢直觉）。所以真正的权重用 fp32 累加，每步再"复制"一份 fp16 给前向用。

加起来：2 + 2 + 4 + 4 + 4 = 16 字节/参数。这就是著名的 "16 bytes per parameter"。

> 7.5B 模型 → 16 × 7.5 ≈ 120 GB 模型状态。一张 80GB 卡直接爆掉——而推理只需 fp16 参数 15GB。差距就在梯度和那 12Ψ 的优化器状态。

激活是另一笔账，正比于 batch × seq_len × layers × hidden。它的省法是激活重计算 / 梯度检查点（gradient checkpointing）：前向时只保留每层的"入口"，反向需要中间激活时临时重算一遍。用约 33% 的额外算力，换取激活显存从 O(层数) 降到 O(√层数) 量级。这是典型的"算力换显存"。

回到 ZeRO

现在看第15课的数据并行（DP）的浪费：N 张卡，每张都跑一份完整模型、各自算梯度、再 All-Reduce 同步。问题是——每张卡都存了一整份 16Ψ 的模型状态，完全冗余。N=64 时，同样的优化器状态被复制了 64 遍。

ZeRO 的洞见极其朴素：这些状态不必人人都存全份；分片存储，需要时再用通信临时凑齐。 它分三级递进（N 为卡数）：

- ZeRO-1（切优化器状态）：那 12Ψ 分成 N 份，每卡只存 12Ψ/N。每卡显存 = 4Ψ + 12Ψ/N。这部分几乎"白捡"，因为优化器更新本来就能各管一段。
- ZeRO-2（再切梯度）：梯度 2Ψ 也分片，每卡只保留自己负责那段参数的梯度。每卡 = 2Ψ + 14Ψ/N。
- ZeRO-3（再切参数）：连 fp16 参数 2Ψ 也分片。每卡 = 16Ψ/N。代价是：前向/反向要用到某层完整权重时，得临时 All-Gather（第15课原语）把这层参数凑齐，用完即扔。

代入 7.5B、N=64：DP 每卡 120GB → ZeRO-3 每卡 ≈ 1.9GB（模型状态）。这就是"训万亿参数"的底气。

核心权衡：ZeRO 用通信换显存。ZeRO-1/2 的通信量和普通 DP 基本持平（几乎免费的午餐）；ZeRO-3 因为要反复 All-Gather 参数，通信量约增至 1.5 倍。和第15课的 TP/PP 相比，ZeRO 最大的好处是保持了 DP 的编程模型——你不用手工把模型按层或按注意力头切开，框架自动分片。PyTorch FSDP ≈ ZeRO-3。此外 ZeRO-Offload 还能把优化器状态甩到 CPU 内存，让单卡也能训大模型（用带宽换容量）。

一句话记忆：TP/PP 是"把模型切开算"，ZeRO 是"把冗余的副本切开存"。
