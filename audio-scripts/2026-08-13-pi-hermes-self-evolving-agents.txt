你现在不用看屏幕。这是一份关于 Pi、Hermes，以及所谓自主进化 Agent 的源码导读。

先讲结论。Pi 更像一套精干的 Agent 发动机和编码工作台；Hermes 更像一套已经装好桌面端、消息入口、定时任务、长期记忆和技能管理的个人 Agent 操作系统。GenericAgent 用很少的 Python 代码，让 Agent 在完成任务后把路径沉淀成技能。AgentEvolver 则不是桌面助理，而是一个训练框架，它通过自动出题、经验复用、轨迹归因和强化学习，尝试更新模型策略。

它们都可以说自己会进化，但进化的对象不同。有的改变当前会话，有的写长期记忆，有的生成 Skill 文件，有的真的训练模型权重。理解这一点，比记住任何项目的宣传语更重要。

先从最小 Agent 循环开始。用户给出目标，程序把系统提示、历史消息和工具列表交给模型。模型如果返回普通文本，这一轮结束。模型如果返回工具调用，程序就校验参数，执行终端、文件、浏览器或其他工具，再把结果交回模型。模型继续决定下一步，直到没有工具调用，或者达到预算、被中断、发生错误。

模型不直接操作电脑。真正执行动作的是循环外面的 harness，也就是承载模型的运行框架。权限确认、失败重试、上下文压缩、状态保存、并行工具、审计记录，这些都由 harness 完成。今天 Agent 产品的差异，主要也在这些工程细节，而不是那几行 while 循环。

第一部分讲 Pi。

Pi 的源码是一个 TypeScript monorepo。它把统一模型接口、Agent core、coding agent、终端界面、Web 组件和协议拆成独立包。这个结构的意义是，Agent 内核不必知道你用 Claude、OpenAI 还是其他模型，也不必知道你最终做成终端工具、网页聊天，还是嵌进自己的产品。

Pi 的 agent loop 有内外两层循环。内层负责模型回复、工具调用和用户中途追加的 steering 消息；外层在 Agent 本来准备结束时，再看有没有 follow-up 消息。整个过程会持续发出事件，比如消息开始、流式文本更新、工具开始、工具结束、本轮结束。界面可以订阅这些事件，所以不需要猜 Agent 是卡住了，还是正在调用工具。

Pi 默认能并行执行一批工具，但它保留确定性。如果有一个工具声明必须串行，整批调用就串行。并行工具谁先完成，完成事件就可以先显示；可写回模型上下文时，结果仍按原始调用顺序排列。这样既有速度，也不会因为机器调度顺序不同，让下一轮上下文变得不可预测。

Pi 还提供工具调用前后钩子、上下文转换、下一轮准备、优雅停止等接口。权限拦截、审计、模型切换、压缩，都可以在核心循环外实现。它的价值不是替所有人规定一个复杂 Agent 应该长什么样，而是提供一组边界清晰、容易组合的零件。

Pi 支持 Agent Skills 标准。启动时只把技能名称和描述放进提示，真正匹配任务后才读取完整的 Skill 文档、脚本和参考资料。这叫渐进披露，避免几十份说明同时占满上下文。用户也可以让 Pi 为自己的任务创建 Skill。

但这里要注意措辞。Pi 是可自扩展的，不代表它默认一直在后台改进自己。它提供 Skill、extension 和 hook，可是何时创建、怎样验证、是否整理，通常由用户、项目规则或外部扩展决定。Pi 更像给 Agent 一门好用的编程语言，而不是自动替 Agent 安排一套学校制度。

第二部分讲 Hermes。

Hermes 的覆盖面更大。它可以从命令行、终端界面、Electron 桌面端、网页，以及 Telegram、Discord、Slack 等消息入口使用。同一个后端还能在本地、Docker、SSH 或云环境运行。定时器可以无人值守地唤醒任务，delegate 可以启动隔离子 Agent，会话库存储历史并支持搜索。

Hermes 的桌面端不是把所有能力重写一遍。桌面渲染器通过 JSON RPC 连接 Python 后端。某种工具是否对当前用户可见，应该由 session 的平台身份决定，而不是简单检查 Python 进程是不是 Electron 拉起的。这样桌面客户端即使连接远程服务器，也能得到正确的桌面能力。

Hermes 真正有意思的自我改进，发生在 Skill 层。它的 skill manager 可以创建、修改、追加文件、归档技能。Agent 做完复杂或容易出错的任务后，可以把流程、坑点、验证方法、脚本和模板写到用户技能目录。下一次遇到相似任务，Agent 先匹配技能描述，再按需读取完整内容。

这不是模型权重更新，而是外部化策略更新。可以把它理解为工程师写运行手册。第一次排障靠临场搜索和推理；第二次直接按照经过验证的步骤做。普通文件容易审阅、比较、回滚，也比每次加载整段历史更省 token。

问题是，Agent 越勤奋，技能库越可能变乱。一次任务一个 Skill，会产生大量重复、狭窄、过期的说明。Hermes 为此增加了 Curator，也就是技能管理员。

Curator 记录每个 Agent 创建技能的查看次数、使用次数、修改次数、最后活动时间、状态和固定标记。长期不用的技能会从 active 变成 stale，再进入可恢复的 archive。它不会自动物理删除。被 pin 的技能不会自动归档。用户手写、从 Hub 安装或外部目录加载的技能，默认也不归它管理。

更复杂的整理，比如把五个非常窄的技能合并成一个领域级 umbrella Skill，可以交给独立后台 Agent。这个功能默认关闭，需要用户明确开启。后台 Agent 有独立会话，是因为 Hermes 非常重视提示缓存。如果在进行中的对话里突然更换工具列表、重建系统提示，缓存前缀会失效，成本明显增加。独立维护既避免污染用户对话，也能控制它能修改的范围。

这已经比简单的“任务后写个笔记”成熟很多，但仍不是魔法。错误经验可能被固化，技能描述可能检索不到，网页和 API 改版后旧流程会失效。社区 issue 也出现过后台整理长时间循环和巨大 token 消耗的案例。系统解决了经验如何产生、保存和治理的问题，却还没有自动证明每一份经验都正确。

因此评估 Hermes 是否变聪明，不能只数 Skill 数量。应该看相似任务成功率是否提高，工具步骤是否减少，人工接管是否下降，环境变化后能否识别技能过期，以及禁用新增技能后提升是否消失。

第三部分讲 GenericAgent。

如果把最近热门的 Python 自主进化 Agent 当成一条产品路线，GenericAgent 很有代表性。它的核心 agent loop 只有一百多行。循环调用模型，解析工具，交给 handler，再把结果变成下一条消息。复杂能力主要放在 handler、分层记忆和 SOP 里。

GenericAgent 宣称只用九个原子工具，包括执行代码、文件读写、网页扫描、浏览器 JavaScript、询问用户、短期 checkpoint 和长期记忆更新。执行代码是它最强的元工具。Agent 可以安装依赖、写脚本、调用外部 API，再把成功路径写进记忆。

它把记忆分成五层。零层是元规则，一层是索引，二层是稳定事实，三层是任务技能和操作流程，四层是原始会话归档。面对新任务，Agent 先探索，安装和调试需要的能力，验证成功后再固化为 Skill。下次遇到相似任务，就直接召回。

这种设计的魅力在于极简。一个很强的基础模型，加代码执行和真实浏览器，确实能在很小框架里完成很多任务。风险也来自同一处。代码执行权意味着很大的安全边界。任务完成并不自动等于技能经过回归测试。网页改版和权限变化会让 SOP 过期。项目方关于完全自举和 token 节省的结果，也应该和独立复现分开看。

GenericAgent 与 Hermes 都属于运行时资产增长。Hermes 更重平台、来源边界和生命周期治理；GenericAgent 更重少量种子代码、真实电脑控制和让 Agent 自己搭环境。

第四部分讲 AgentEvolver。

AgentEvolver 不是另一款桌面 Agent，而是 Agentic reinforcement learning，也就是智能体强化学习的训练框架。它把自进化拆成三个机制。

第一是 self questioning，Agent 探索环境并自动生成任务，减少人工构建数据集。第二是 self navigating，从历史轨迹中提炼经验，放进下一批 rollout，引导探索。第三是 self attributing，对长轨迹中的中间步骤做归因，把最终成败更细地分配到动作，再用于策略优化。

源码结构与这个流程一致。环境管理器负责沙盒和 rollout，任务管理器负责数据、环境配置和 reward，经验管理器为新任务挑选历史经验，上下文管理器处理多轮消息，归因模块做语义信用分配，trainer 接到分布式强化学习栈。

这条路线真正会更新模型权重。Agent 给自己出题，在环境中产生轨迹，环境或判分器给奖励，归因模块判断哪些步骤贡献了结果，训练器再改变 policy。下一次变强，不是因为多读一份 Markdown，而是相似决策的概率被训练改变。

它也更昂贵。你需要可重置的环境、可信奖励、足够多的 rollout、GPU 和严格评测。奖励写错会稳定训练出错误行为；自动出题太窄会强化偏见；经验注入有效，也不等于权重更新一定有效。因此 AgentEvolver 更适合研究和模型训练团队，而不是普通用户在电脑后台长期运行。

到这里，可以把自主进化分成四层。

第一层是会话适应，只改变当前上下文和工作 checkpoint。第二层是记忆适应，保存事实、历史摘要和用户模型。第三层是策略资产适应，写 Skill、SOP、脚本和模板。第四层是参数适应，训练模型 policy 和权重。

Pi 主要提供第一层到第三层所需的可扩展 runtime，但不强制自动闭环。Hermes 和 GenericAgent 重点做第二、第三层。AgentEvolver 进一步做第四层。很多产品把第二或第三层叫 self evolving 并没有错，只是它不是在线微调。

如果要选，做开发工具、IDE 助手或垂直 Agent runtime，我会先看 Pi。做二十四小时在线、跨消息渠道、带定时任务和长期技能的个人助理，我会看 Hermes。想用最少代码研究电脑操作和个人 Skill 树，可以试 GenericAgent，但应放在隔离环境。想训练更强的工具调用模型，并且已经有环境、grader、GPU 和评测能力，才适合 AgentEvolver。

最后给一个判断某个 Agent 是否真的进化的实验。准备三十个可重复任务，分十个领域，每个领域三个难度。第一轮禁止旧 Skill。完成后允许系统沉淀经验。隔一天，在干净会话中执行同类但不完全相同的任务。记录成功率、人工接管、工具步数、重复失败、token、成本、耗时和技能召回。再禁用新增资产复测。

只有第二轮稳定变好，而且关闭新增技能或记忆后提升消失，才能说明学习闭环产生了因果效果。一次华丽的长任务，只能证明模型和工具当时完成了任务，不能证明系统会持续成长。

真正值得关注的，不是哪个项目最会说自主进化，而是谁能回答三个问题。它改了什么？凭什么认为改对了？出错以后怎样恢复？

Pi 把执行内核做得干净。Hermes 把长期运行和 Skill 生命周期做成产品。GenericAgent 展示极简框架也能长出复杂能力。AgentEvolver 把问题推进到自动数据和策略训练。把这四个截面放在一起，我们看到的不是四个互相替代的软件，而是一套正在成形的 Agent 技术栈。
