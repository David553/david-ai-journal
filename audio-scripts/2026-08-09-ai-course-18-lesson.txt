第18课：让大模型"抄近道" —— 量化部署、蒸馏与投机解码

本课目标

课程路线走到 B18：推理优化。前面几课你已经知道：decode 阶段是 memory-bound 的（第13课），每生成一个 token 都要把全部权重从 HBM 搬进计算单元一遍；continuous batching 和 PagedAttention（第17课）解决的是"怎么把很多请求塞进一张卡"，但单个请求的生成速度并没有变快——自回归一次一个 token 的串行本质还在。

本课讲三条"让推理本身变快"的路：把权重变小（量化部署）、把模型变小（蒸馏）、把串行变并行（投机解码）。学完你能解释：为什么一个小模型"打草稿"、大模型"批改"，就能在数学上保证输出分布完全不变的前提下加速 2-3 倍。

经典案例

背景铺垫

1. 推理优化的三类思路

decode 每步的耗时 ≈ 权重字节数 ÷ 显存带宽（第13课的 memory-bound 结论）。想变快，只有三个方向：

- 每字节更少：量化。第14课讲过整数量化、scale、outlier，推理部署中最常用的是 weight-only 量化——只把权重压到 INT4/INT8，激活保持 BF16，计算前反量化回来。因为瓶颈在"搬权重"而不在"算"，权重减半搬运时间就近似减半。GPTQ、AWQ 就是这类方法（知道名字即可）。
- 模型本身更小：蒸馏（下面讲）。
- 一次前向吐出多个 token：投机解码（本课主菜）。

2. 知识蒸馏：让小模型"抄大模型的作业"

直接训一个小模型，用的是 one-hot 标签："下一个词是'苹果'，其他都是 0"。但大模型（teacher）的 softmax 输出包含更丰富的信息：苹果 0.6, 香蕉 0.25, 橘子 0.1...——它告诉你"香蕉也挺合理，橘子勉强"。这种概率分布叫软标签（soft label）。

蒸馏出的小模型快，但有损——它终究不是大模型。有没有既快又完全无损的办法？

3. 投机解码的核心洞察：验证比生成便宜

关键事实（由第13课直接推出）：decode 时 GPU 的算力大量闲置，一次前向传 1 个 token 和传 5 个 token，耗时几乎一样——因为时间花在搬权重上，权重只需搬一遍，多几个 token 只是多一点点计算，算力反正是白送的。这正是 prefill 能并行处理整段 prompt 的原因。

那么矛盾在哪？自回归生成第 5 个 token 必须先知道第 4 个，没法自己并行。但验证可以并行：如果有人先猜好了 5 个 token，大模型一次前向就能同时算出这 5 个位置各自的"标准答案分布"，逐个检查猜得对不对。

4. 怎么算"猜对"？接受-拒绝采样保证无损

如果只在 draft 的 token 恰好等于 target 贪心结果时才接受，那带采样的生成就没法用了。Leviathan 等人的精妙之处是一套接受-拒绝规则，数学上保证最终输出分布与 target 模型独立采样一模一样：

设 draft 模型在某位置给出分布 q，采出了 token x；target 模型算出分布 p。

- 以概率 min(1, p(x)/q(x)) 接受 x。直觉：target 觉得 x 比 draft 想的还合理（p≥q），必收；target 觉得没那么合理，按比例掷骰子。
- 一旦拒绝，从残差分布 norm(max(0, p − q)) 中重采一个 token 顶替，并丢弃后面所有草稿。残差分布补的恰好是"q 采过头、p 还欠缺"的那部分概率质量，两边一拼，合计分布严格等于 p。

所以投机解码是无损加速：不是近似，输出的统计性质和直接跑大模型分毫不差。这是它和量化、蒸馏最本质的区别。

5. 收益由接受率决定

设平均接受率为 α（draft 和 target 越"像"越高），每轮猜 k 个，则每次大模型前向期望产出约 (1−α^(k+1))/(1−α) 个 token。α≈0.8、k=5 时约 3.7 个——接近 3 倍多加速。draft 模型常用同系列小模型（如 70B 配 7B），或干脆蒸馏一个专属 draft——第 2 节的蒸馏在这里派上了用场：蒸馏得越像，α 越高。

回到案例

现在可以完整串起 Leviathan et al. 2023：它把"decode 算力闲置"（Roofline 视角）转化为"用闲置算力做并行验证"，用接受-拒绝采样证明了无损性，并给出了 α 与加速比的理论分析。后续演化你只需知道概念：Medusa 不用独立 draft 模型，直接在大模型上加几个预测头一次猜多个 token（并行解码）；EAGLE 用大模型自己的隐状态帮 draft 猜得更准；再配合 token 树验证——一次验证多条候选分支，进一步提高期望接受长度。它们都建立在今天这套"猜-验证-接受/拒绝"框架上。
