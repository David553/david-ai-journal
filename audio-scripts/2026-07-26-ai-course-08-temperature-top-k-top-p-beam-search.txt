第8课：模型如何"选词" —— temperature、top-k/top-p 与 beam search

本课目标

回到知识图谱：第2课我们知道了模型每一步会吐出 logits，经过 softmax 变成整个词表上的概率分布，然后"选一个词"。当时我们只讲了两种最朴素的选法——贪心解码（永远选概率最高的）和采样（按概率掷骰子）。但这两者中间和之外，还藏着一整套决定生成质量的"解码策略"。

学完这一课，你能回答：为什么 ChatGPT 有个 temperature 参数？为什么调高它会"更有创意"也更容易胡说？为什么翻译系统爱用 beam search，而聊天/写作却要用采样？以及一个反直觉的事实——为什么"每一步都选最可能的词"反而会让文本变得又蠢又重复。

今日经典案例

没有合适的新论文，用 2019 年的经典 《The Curious Case of Neural Text Degeneration》（Holtzman 等）作案例。它提出了如今最主流的解码方法 top-p / nucleus sampling（核采样），并用实验揭示了"最大概率解码会导致文本退化"这一现象。

背景铺垫

1. 复习：一步生成 = 词表上的一个概率分布

模型在第 t 步输出 logits 向量 $z$（长度 = 词表大小 V，可能 5 万到 15 万），softmax 把它变成概率：

$$p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$$

所有 $p_i$ 加起来是 1。解码策略要做的，就是从这个分布里挑一个 token 作为本步输出。 挑完拼回输入，再算下一步（这就是第1课的自回归）。

2. Temperature：给分布"调锐度"

温度 T 在 softmax 之前把 logits 除以 T：

$$p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$

- T → 小（如 0.5）：logits 差距被放大，高概率的词更突出，分布变"尖"，输出更确定、更保守。
- T = 1：原始分布。
- T → 大（如 1.5）：差距被压平，分布变"平"，冷门词也有机会，输出更随机、更"有创意"，但也更容易语无伦次。
- T → 0：退化成贪心解码（永远选最大）。

类比：T 就像掷骰子前捏骰子。T 小 = 灌了铅的骰子，几乎总是同一面；T 大 = 每一面都差不多，纯看运气。

3. top-k：只在前 k 名里抽

纯采样的问题：词表里有几万个词，哪怕每个烂词只有 0.00001 的概率，累加起来也有可观概率抽到一个离谱的词，一旦抽中就可能带偏整句话。

top-k 的做法：只保留概率最高的 k 个 token（比如 k=50），其余全部置零，把这 k 个重新归一化后再采样。等于"只在候选名单里掷骰子"。

缺点：k 是固定的。有时模型很确定（一个词占 95%），k=50 会硬塞进 49 个垃圾候选；有时模型很犹豫（前 200 个词都合理），k=50 又把好词砍掉了。

4. top-p / nucleus：让候选集大小随场景自适应（本课核心）

核采样不固定"取几个"，而是固定"取多少概率质量"。给定阈值 p（如 0.9）：把 token 按概率从高到低排序，从头累加，直到累计概率刚超过 p，就在这一小撮 token（称为 nucleus，核）里采样。

$$V^{(p)} = \text{最小的集合，使得} \sum_{i \in V^{(p)}} p_i \ge p$$

- 模型很确定时：可能一两个词就凑够 0.9，候选集自动变小 → 稳。
- 模型很犹豫时：需要几十个词才凑够 0.9，候选集自动变大 → 多样。

这正是它比 top-k 优雅的地方：候选集大小随分布的"平坦程度"自动伸缩。

5. beam search：并行留住多条候选序列

前面都是"逐步只留一个词"。beam search 换个思路：同时维护 b 条最优部分序列（beam，束宽 b）。每步把每条序列各扩展所有可能的下一个词，用整句的累计 log 概率打分，只保留总分最高的 b 条，其余剪掉。最后返回整体得分最高的序列。

它近似地在找"整句联合概率最大"的序列，而不是贪心那样每步局部最优。翻译、摘要这类"有标准答案、要准确"的任务爱用它。但它在开放式写作/聊天里表现很差——见下。

回到论文

Holtzman 等人的核心观察分两层：

（1）最大化概率 ≠ 好文本。 他们发现用 beam search 或贪心去"最大化概率"生成开放式文本，结果是大量重复（"I don't know. I don't know. I don't know…"）且乏味。原因很反直觉：人类真实语言其实不总走高概率路径——真人说话时每个词的概率是上下起伏的，而机器一味挑最大概率，就掉进了一个"高概率但退化"的死循环。论文用图展示：人类文本的 token 概率剧烈波动，beam search 文本却平滑地贴在高概率区——恰恰因此不像人话。

（2）纯采样又太野。 直接按完整分布采样，会因为那条长长的"低概率尾巴"（几万个烂词的概率累加）时不时抽到离谱词，导致语无伦次。

核采样正是这对矛盾的解法：砍掉不可靠的长尾（解决问题2），但在剩下的"核"里保留采样的随机性和多样性（解决问题1）。它不固定候选数量，而按概率质量动态裁剪，兼顾流畅与多样。这就是今天几乎所有对话/写作模型默认用 temperature + top-p 组合的原因。
